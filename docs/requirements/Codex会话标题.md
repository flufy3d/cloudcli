# Codex 会话标题

> 基准：2.10.0 / 2026-10-21

用户新建 Codex 会话时，侧栏先显示首句。正常聊天成功结束后，CloudCLI 在后台生成短标题，保存到 Codex 原生线程，再同步到本地。侧栏、当前会话顶部和浏览器标题使用同一份名称；标题更新不添加消息，不刷新聊天历史，不改变会话排序或关注标记。

打开旧会话不会发起命名请求。没有原生名称的旧会话，在下一次正常聊天成功后，用历史中最早的真实用户文字生成标题。注入的工作区说明、环境信息和工具记录不作为任务内容。没有可用文字时保留原名。已有原生名称时只同步，不再生成。

用户手动命名优先。归档、删除、分支会话和原生线程映射变化都会使旧任务失效。用户停止聊天、聊天失败、后台工具结果接续不触发自动命名。关闭驻留和驻留容量满后回退短连接的成功聊天也可以命名。

## 开关与请求成本

功能默认开启，设置保存在应用数据库。读取 `GET /api/providers/codex/session-titles/settings`，写入 `PUT /api/providers/codex/session-titles/settings`，请求体为 `{"enabled":false}` 或 `{"enabled":true}`。接口使用应用现有认证。当前没有新增页面开关。

关闭设置会停止接收任务，并取消排队和进行中的未提交结果。已有名称保留。已经发给 Codex 的保存请求可能完成，关闭设置不能撤回该请求，也不能退还已消耗的额度。

自动命名会增加模型请求。实际线程使用 OpenAI 提供方、当前登录方式为 ChatGPT 账号、模型目录含 `gpt-5.6-luna` 时，标题使用该模型和 `low` 强度。其他情况使用实际聊天模型，并从目录支持的低强度中选择；目录没有适用强度就不传。不能保证免费，也不能保证使用独立保留额度。认证和用户级配置与引擎使用同一个 `CODEX_HOME`；未设置时使用 `~/.codex`。

## 失败与并发

任务在进程内串行执行，同一个应用会话与原生线程的在途任务合并。从入队开始计算三十秒总截止时间，排队也占用时间。多个会话同时结束时，后排任务可能在启动前过期。失败保留原名，不向正式聊天追加错误，不定时重试；下一次正常聊天成功后可以再次尝试。

原生保存结果不明时，任务先读回原生名称，确认存在后再同步本地。原生保存成功、本地保存失败时，下次任务只补同步。Codex 的读取和保存接口没有条件写入参数，另一客户端在最后一次读取与保存之间改名仍存在竞争窗口。本地手动命名受数据库条件写入保护。

实现机制与验证入口见 [Provider 架构](../core/providers.md) 和 [设计稿](../design/Codex会话标题.md)。
