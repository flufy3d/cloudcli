# 盘符工作区根包含判断修复

> 状态：已实施
> 基准：2.21.0 / 2026-11-14

## 问题

配置 `WORKSPACES_ROOTS=C:\;D:\` 后，文件夹浏览器能显示盘符按钮并进入 `D:\`，但进入 `D:\Projects` 时返回：

```
Workspace path must be within the allowed workspace roots: C:\Users\JamesChen-360world, C:\, D:\
```

## 根因

`normalizeProjectPath` 会保留文件系统根的尾部分隔符（`C:\`、`/`）。包含判断统一写成
``startsWith(`${root}${path.sep}`)``，对这类根会拼出 `C:\\` 或 `//`，导致根的所有子路径都不匹配。
现有测试只验证了盘符根自身（`allowDriveRoot`），没有覆盖根下的子目录。

## 范围

只修 `server/shared/utils.ts` 内的根包含比较及其测试；不改变默认工作区策略、不扩大允许根，
也不改动盘符列表的配置开关。

## 方案

新增模块内私有函数 `isPathInsideRoot(target, root)`：根已以分隔符结尾时直接作为前缀，否则补一个分隔符，
再统一用于 `validateWorkspacePath`（普通路径与符号链接目标）、`resolvePathUnderRoots`、
`validatePathSecurity` 和 `isSystemTemporaryWorkspacePath`。

`isForbiddenSystemDirectory` 与 `file-tree.module.ts` 的禁止目录判断保持不变：它们的 `/` 条目表示
“根自身不可用”，若改成同样的前缀语义会把所有 POSIX 路径都判为系统目录。

## 验证

- 新增回归测试：`WORKSPACES_ROOTS` 设为当前磁盘/文件系统根时，用户主目录应通过校验。
- `npx tsx --tsconfig server/tsconfig.json --test server/shared/tests/validate-workspace-path.test.ts`
- `npm run typecheck`
- 构建后在 `WORKSPACES_ROOTS` 含盘符根的环境下实测浏览 `D:\Projects`。

## 风险

- 盘符根之下的所有目录重新可注册为项目，这正是 `WORKSPACES_ROOTS` 多根配置的既定语义。
- 真正禁止的系统目录仍由 `isForbiddenSystemDirectory` 拦截；本次不改变它的 `/` 特例。
