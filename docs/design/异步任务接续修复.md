# 异步任务接续修复

> 状态：目标工作树修复与独立本地验收通过；Luna（`gpt-6-luna`，`high`）实施；[验收证据](../archive/异步任务接续修复验收_2026-10-17.md)；未部署
> 基准：2026-10-17；验收对象为基线 `d7d9588c8d6fb72ce018ad7faf0f74d8f8973923` 上的异步任务接续实现

## 修复目标与依据

任务从原聊天登记后，执行器立即返回任务 ID 并在后台继续执行。任务结束后，CloudCLI 保存真实结果，等原聊天空闲再触发汇报。关闭浏览器、父回合结束或隔离宿主重启都不能丢结果。引擎失败不能记录为成功，发送结果不明不能盲目重投。

实现遵循[原设计](异步任务接续.md)，逐项消除[验收报告](../archive/异步任务接续验收_2026-10-17.md)中的 S1—S4、R1—R7。验收报告的实测包括匿名读取和取消返回 200、真实 CLI 登记返回 401、失败回答记录成 delivered、过期 ISO 租约无法接管、取消结果恢复成成功。现有专项测试没有覆盖这些路径。

保留已有异步任务实现，在功能分支修复。生产发布、部署与 PM2 操作不在本次修复范围。新建任务管理页面、改造所有引擎、引入独立消息中间件不在本次范围。其他引擎原生后台任务只做回归，不额外接入宿主投递。

## 接入证据与实施选择

包内 Codex `0.159.2` 的隔离实测表明，`workspace-write`、`approvalPolicy:never` 下，命令工具调用本机临时 HTTP 服务失败，输出 `CALLBACK_DENIED`、退出码为 1，服务收到请求数为零。因此沙箱内 CLI → HTTP 不能承担默认登记主路。任务回调不是简单的请求字段修复，不能靠放宽网络权限接通。

以下探针已经使用真实包内 app-server 运行。测试线程均独立于用户聊天，测试后归档；请求没有真实任务凭证或生产数据。

| 接口路径 | 实测证据 | 使用限制 |
| --- | --- | --- |
| 原回合结束后提交工具结果 | `turn/start.toolOutput` 触发新回答并成功结束，历史分页找到原事件标识 | 宿主仍须负责持久队列和真实终态 |
| 动态工具反向请求 | 新线程的 `dynamicTools` 产生带 threadId/turnId 的 `item/tool/call` | 属于实验接口；当前 ThreadResumeParams 没有 dynamicTools 字段，不能只考虑新聊天 |
| 既有聊天接入 stdio MCP | 先建立原线程、关闭连接，再通过 `thread/resume` 的本次 config 加入测试 MCP；同一 threadId 下实际工具调用成功 | 没有改用户全局 MCP 配置；只读工具和 on-request 下的测试工具均有真实调用证据 |
| MCP 审批边界 | 未标为只读的测试工具在 never 策略下被拒绝，on-request 下实际调用成功 | 生产工具必须如实声明副作用，不伪装只读、不自动修改审批策略 |
| 独立沙箱命令 | `command/exec` 指定 workspaceWrite、networkAccess:false，在临时工作目录写入测试文件并返回成功 | 尚需补真实越界拒绝、环境过滤、长任务和独立执行器生命周期验收 |

推荐标准 stdio MCP 作为 Codex 的宿主任务入口。模型调用 `cloudcli_task_run/status/cancel_notification`；专用 MCP 进程只传递宿主任务请求，宿主从有限权限上下文绑定原用户、聊天和运行。实际任务由独立后台执行器通过官方 `command/exec` 在原沙箱范围执行，完成结果由执行器落盘和宿主收取；沙箱中的任务命令不再承担 HTTP 登记或回调。

stdio MCP 使用已有聊天可接入的标准工具协议；动态工具方案需要处理既有线程的接口限制和实验接口，暂不选。工作区文件信箱虽可避免网络，但需要另行维护签名请求、确认文件、监听、工作区污染及文件竞争，也暂不选。

这个选择增加专用 stdio MCP 桥和隔离执行连接，变更了原设计中的聊天派发入口。代价是每次运行需要加载受控工具，后台任务增加一个受管理的执行连接，审批策略不允许调用时任务会明确拒绝。好处是无须放宽沙箱网络，也无须让模型命令读取登记密钥。功能总开关仍默认关闭。本接法保持原任务范围和权限边界，按用户已批准的修复任务实施。

协议依据：[官方 App Server](https://learn.chatgpt.com/docs/app-server) 的 MCP、独立命令和工具结果接口。探针脚本位于本机 `/tmp/cloudcli-codex-*-protocol.mjs`，临时证据目录由脚本输出；这些文件是一次性验证产物，不能替代最终产品链路验收。交付报告保存脱敏结论及可复验步骤，不依赖临时目录永久存在。

## 实施决策

用户操作与任务执行器使用不同凭证。用户认证保护任务查询、取消和人工处置，并校验任务所属用户。原运行的登记凭证绑定实际用户、CloudCLI 会话和运行 ID；请求正文不能覆盖归属。任务回调凭证只用于该任务的结果提交及必要查询。凭证持久化只存摘要，原运行结束后撤销登记权，已登记任务的结果补录不跟着原回合一起失效。

当前 sessions 表没有用户归属列。本次以可信聊天运行上下文和任务的 `user_id` 作为任务归属来源，不能虚构一条 `session.user_id` 校验，也不能借此宣称整个应用已具备聊天多租户隔离。正常用户认证与平台模式都复用现行身份解析，任务凭证不能因平台模式自动免验。

运行登记、有限权限凭证、实际目录由宿主生成。在网关到运行时的可信内部契约中传递本轮上下文，为专用 MCP 桥提供登记能力，不写全局敏感 `process.env`；普通客户端 options 不得注入或覆盖这份能力。不把凭证值写进会话 config、rollout、工具参数或日志。若通过 app-server 子进程环境和 MCP 的 env_vars 传递能力，必须让命令工具的环境过滤策略排除这些变量，并在真实沙箱探针中确认。任务命令和后台执行连接也必须移除登记凭证、任务管理凭证和用户认证信息。

MCP 桥先向宿主登记，宿主确认登记和独立 Node 后台 worker 启动后返回任务 ID。worker 独立持有一个执行用 app-server 连接，以 `command/exec` 和 argv 启动任务命令，不复用原回答连接的生命周期。沙箱策略和工作目录来自可信原运行，模型不能请求更宽权限。禁止用明确绕过沙箱的 `thread/shellCommand` 或 `process/spawn` 替代。启动失败写失败结果。长任务不能被当前客户端的短请求超时误杀，任务超时和输出上限需要明确配置与测试。

worker 在沙箱外负责管理日志、将结果原子落入宿主管理目录，由宿主扫描补录；实际任务命令仍在原沙箱内。

独立入口加载不得打开宿主数据库。安装包验证发现 providers barrel 经 Codex、ZCode 的通知依赖触发 `notifications/vapid-keys.service.ts` 顶层 `getConnection()`；worker 不带 `DATABASE_PATH` 时会打开安装包 `dist-server/database/auth.db` 的 legacy fallback 文件。这不是已配置的生产数据库。将连接获取延迟到真实读取 VAPID 密钥的调用内，保留通知缓存语义，不给 worker 传入宿主数据库。先用隔离数据库哨兵与 CLI、MCP、worker 子进程负例复现，再验证三入口不创建数据库；有效 worker 仍须执行成功。该修复纳入后台执行隔离范围，同时回归真实通知密钥读取。宿主启动扫描与在线周期扫描共同兜底；不能只补启动时已经存在的文件。所有路径来自可信任务登记，读取时核对真实路径、目录边界、符号链接和文件大小。

CLI 提供经过用户认证的宿主侧管理入口，不执行任意外部 `run` 命令。Codex 派发只走本轮 MCP；旧登记 HTTP 路由明确拒绝缺少可信运行的登记。原设计的使用说明、验收入口与架构图需要随本接法同步，不能一处写 MCP、一处继续要求不可用的沙箱内 HTTP。MCP 工具的审批拒绝或等待沿用原策略并明确呈现，不伪装为登记成功。

任务登记时保存可信运行的原引擎线程 ID、工作目录、沙箱类型与网络权限、审批策略。原线程 ID 以宿主当时已绑定的引擎 ID 为准，不接受工具参数指定。发送和历史核对都使用任务快照；如果聊天已经 fork、换目录或引擎映射改变，事件进入 needs_review，不跟随新映射发送。快照缺失的存量任务不能猜测原目标。归档聊天暂停，恢复后重新核对。

网关返回有类型的占用结果和真实运行结果，区分会话忙、目标失效、不支持、已接收、成功、失败、中断和不确定。Codex 适配器在请求接受时上报真实回合 ID，不能等回答结束后才猜。数据库回执更新需要合法前置状态和当前尝试身份，过期执行者不能覆盖新执行者。

双子进程并发同结果上报不能以 `SQLITE_BUSY` 代替幂等回执。真实验收发现新增 repository 的延迟事务先读后写产生锁升级竞争；先补实际多进程失败测试，再在新增读写事务边界取得写入保留锁，让数据库顺序处理幂等校验和领取。不对外部引擎发送做盲重试。检查同模块的结果写入、领取及人工重试事务，并验证两进程同结果只生成一个事件、同事件只有一个领取者。

租约统一使用可比较的时间表示；优先数据库整数毫秒，所有调用共用可注入时钟。增量迁移必须考虑目标树已经运行过、保存了 ISO 租约的数据库，不以“功能还没发布”为由跳过已有数据。任务终态、待投递记录仍在同一事务提交。

HTTP 和磁盘结果共用边界解析与规范化摘要计算，拒绝未知状态。取消保留为取消，失败保留为失败。读取错误、数据库异常和结果不明必须有可查询原因，不能被空 catch 吞掉。

历史核对使用 Codex 官方接口和完整分页证据，覆盖 sending、accepted 及关联回答已终结的情况。“未找到”不是“确定未发送”；证据不足进入 needs_review。审批等待不重投，用户中断不自动重新汇报。需要人工重投时创建独立尝试，提示此前可能已执行，保留操作者、原因和旧回执。

自动接续使用集中配置的总开关，默认关闭。MCP 工具的 `notify: true` 明确选择自动汇报；缺凭证、开关关闭或不支持时明确返回原因，不悄悄执行无通知任务。已经登记的任务在总开关关闭后仍可落结果，只停止新投递。任务运行中允许取消未来通知，取消通知不停止任务本身。

## 实施顺序与阶段门槛

每个阶段先补可复现失败的测试，再写实现。测试应调用真实边界，而不是只验证抽出来却未被产品代码调用的辅助函数。Luna 实施一个阶段后向主 Agent 回报文件、失败输出、修复后结果及遗留问题；主 Agent 核对后推进下一阶段。

| 阶段 | 修复内容与覆盖发现 | 主要文件或模块 | 进入下一阶段的证据 |
| --- | --- | --- | --- |
| 复现基线 | 固化验收探针，标清 mock、真实 HTTP、真实进程和真实 Codex 的边界 | task-continuations、database、websocket 的测试与一次性探针 | 现有错误在新增负例中稳定失败；旧有通过结果单独保留 |
| 接入前置验证 | 已实测工具结果、历史分页、默认沙箱回调受限、MCP 加入既有聊天及独立命令；补 MCP 权限与执行器隔离负例 | 隔离线程、临时探针、现有 app-server 客户端 | 不增加沙箱权限；工具能力不泄给命令；越界写入和网络仍被拒绝 |
| 数据与边界 | 统一状态、摘要、租约、条件更新；验证凭证有效期；取消保持真实终态（S2、S4、R4） | schema、migration、task repository、结果解析和凭证服务、共享契约 | 真 ISO 遗留数据可迁移；生产路径生成租约能到期；不同内容不能伪装同摘要；HTTP/磁盘负例通过 |
| 真实登记与权限 | 接通运行绑定凭证、stdio MCP 到宿主 API 的契约；保护查询取消；清除硬编码用户（S1、R1） | MCP 桥、task routes/service、websocket 网关、Codex 本轮配置、必要公共类型 | 既有聊天 → 真实 MCP → 宿主 HTTP → 隔离数据库贯通；匿名、跨用户、跨任务、过期与平台模式负例通过 |
| 后台执行与结果补录 | command/exec 独立执行器、环境过滤、可信任务目录、启动确认、在线补录（S3、R2） | MCP 桥、task-runner、后台 worker、Codex 沙箱命令适配、任务服务和恢复服务、构建入口 | 原聊天连接结束后任务完成；任务命令拿不到测试凭证标记且不能越过原沙箱；宿主上线前后产生的离线结果都能补录 |
| 运行与投递回执 | 原子占用、忙则回队列、按聊天调度、真实回合与终态、消息身份（R3、R6） | chat-run-registry、chat-websocket、provider runtime/types、Codex runtime/items/sessions、派发器 | 完成帧失败不记 delivered；竞争不丢通知；忙聊天不堵其他聊天；实时和历史结果身份一致 |
| 重启与用户控制 | 装配真实历史核对、恢复全部相关状态、默认关闭、提前取消、人工处理、目标检查（R5、R7） | 恢复/派发/任务服务、认证路由、server 启动装配 | 真子进程终止/恢复矩阵通过；历史不足不重发；归档暂停；用户能查原因和明确处置 |
| 完整交付 | 全量门禁、包产物、真实 Codex、兄弟场景回归、同步文档和独立审查 | 原设计验证矩阵涉及的模块和文档 | 提交逐场景证据，不以测试数量或 build 成功代替验收 |

文件范围允许上述模块新增必要的内部 TypeScript 文件、测试和 barrel 导出。修改前先查现有公用契约与全部消费者，跨模块走 `index.ts`，共用类型按后端规范放置。启动入口只装配，不内嵌任务业务逻辑。必要前端变更先说明原契约为何不足，并加载前端规范；若需要新增页面或更改产品范围，回写计划并等待确认。

## 必须验证的失败路径

真实 HTTP 测试从实际路由挂载和身份中间件开始，不能直接伪造 `req.user` 后跳过认证。MCP 桥和宿主侧 CLI 的集成测试使用实际服务响应，不用手写假响应。至少包含登记失败不执行命令、错误凭证不能读/取消/提交、普通用户不能操作别人的任务、内部摘要不出响应、任务完成前可取消未来通知。

状态与调度测试通过生产存取路径写租约，使用可控时钟验证到期、同日及跨日边界、旧尝试不能覆盖新尝试、终态不能倒退。通过故障点让事务两次写入之间失败，证明任务和事件同时回滚。并发重复上报同结果只有一条事件，不同内容即使携带同一客户端摘要也必须冲突。

结果解析测试覆盖成功、失败、取消、未知状态、缺字段、错误版本、超长文件、路径越界、符号链接、半写临时文件，以及 HTTP 与磁盘表达同一结果时的幂等性。进程启动失败、信号退出和回调暂时失败不能变成成功。日志和结果里使用假凭证标记检查泄漏，不输出真实秘密。

真实网关加可控引擎测试覆盖：引擎用完成帧报告失败却正常返回 Promise、用户中断、审批等待、检查空闲后用户抢先占用、引擎后台驻留、不同聊天互不阻塞、同聊天多个事件顺序、归档/删除/用户失效/不支持引擎、总开关在有积压事件时关闭。

崩溃测试启动独立子进程并真正终止，再从同一临时数据库恢复。故障点逐项沿用原设计：结果落盘后未补录、事务提交后未唤醒、领取后未发送、发送意图已落库、引擎接受未记回执、回答进行中、回答已结束未记交付，以及历史读取失败。每种情况核对实际回合数量与持久回执，不能只看 UI 没出现重复。

真实 Codex 只用仓库包内版本、独立线程、隔离宿主和临时产物，验证既有聊天接入 MCP 后派发、父回合结束、浏览器关闭、自动汇报、刷新历史、重复上报、用户竞争、失败与重启。新增 MCP 必须只用于本次受控连接，不写用户全局配置。工具审批拒绝、原沙箱网络和文件边界、命令环境过滤均需真实负例。探针或账号限制导致无法验证时，必须保留“真实接通未验收”，不能把 mock 当补足证据。

## 回归与交付

逐阶段跑定向测试。完整交付运行 `npm test`、`npm run test:client`、`npm run typecheck`、`npm run lint`、`npm run build`，并验证打包安装后的执行器入口。必须在最终构建完成后打包；逐字节核对本次后端产品源码、编译文件、包内文件和安装文件，不能只凭 worker 能执行认定包含最后修复。覆盖率按现有工具实测，遵守产品代码 80% 要求；没有输出就写未统计。lint 警告区分已有和新增，失败保留实际输出。检查通过后不无理由重复全量检查。

回归普通 Codex 聊天、定时消息抢断策略、持久草稿排队，以及 ZCode、Claude、Antigravity 的原生后台回报、停止与重连。哪些实际跑过、哪些只读源码、哪些环境受限必须分别列出。
