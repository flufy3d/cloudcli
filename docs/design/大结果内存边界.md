# 大结果内存边界

基准：2026-10-18

状态：已完成（待用户部署）

## 目标与范围

OpenCode 连续读取图片时，工具结果中的内嵌图片同时进入实时重连缓存和全量历史读取。隔离实验使用线上读取器和真实图片结果，重复读取历史可超过 PM2 内存门槛。

全部 provider 的聊天输出使用文件引用表示内嵌图片。模型接收的原始工具结果由引擎管理，CloudCLI 只处理展示副本。图片资源复用现有鉴权接口和图片查看器。

## 实施顺序

1. 用各 provider 的真实归一化入口写图片结果失败测试，用共用 registry 写缓存字节预算及重放缺口测试。
2. 在共用边界落盘内嵌图片，各适配器在解析后、批量保留及重新序列化前调用。相同内容使用稳定文件名，实时与历史引用一致。
3. 数据库记录逐条读取；文件逐行读取。分支选择、工具配对和顺序恢复需要保留的索引只持有轻量展示副本，不持有图片正文。分页保持现有消息身份、总数和顺序契约。
4. 重连缓存同时受条数、单条字节数、每个运行字节数及进程总字节数约束。无法完整重放时返回缺口标记，让浏览器补读历史。
5. 历史缓存按实际展示数据计费，超过预算的单个条目不驻留。工具结果中的资源引用提供查看入口。用户输入保留完整原文供编辑和复制。HTML、PDF、JSON 导出主动读取资源并内嵌，静态附件使用原生展开与下载入口，不依赖 React 事件。
6. 运行 provider 回归、同规模模拟数据内存对照、类型检查、构建与 lint。独立代码审查和产品评审后交付。

## 验收

图片的内嵌正文不进入归一化消息或长期缓存。文字、图片原始字节、工具错误状态均保留。旧会话无需改写引擎数据库，重新读取即可获得资源引用。连续读取及刷新测试比较相同数据、相同入口下的进程内存；峰值测量与功能断言分别报告。

源码里的预算常量是容量依据。预算驱逐不删除图片文件。服务部署由用户执行。

验收记录见 [大结果内存验收](../archive/大结果内存验收_2026-10-18.md)。构建后运行 `node scripts/probe/provider-result-memory.mjs` 可重跑隔离内存检查；追加 `--baseline /path/to/old/package` 可比较旧构建。探针使用临时目录和模拟图片，不启动服务。
