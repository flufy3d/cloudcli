> 基准：2.10.0 / 2026-10-20

修复针对 `5ce5708c` 的驻留生命周期、任务结果接续和任务桥接。驻留默认关闭，修复不包含生产开关、部署或服务重启。

初始化失败必须释放进程和凭证。初始化中关闭会话不能被迟到应答重新登记。归档、容量淘汰和空闲回收共用活动判断，覆盖初始化、运行时准备窗口预留、用户回合、排队输入、待判定回合、后台汇报与未回答的审批。缓冲事件与实时事件使用同一个引擎回合生命周期入口。审批先等待对应回合的归属判定，再选择本轮或会话通道，不能仅等待提交应答。

停止排队输入必须等待提交身份。只有 `thread/queue/delete` 的 `deleted` 为真才报告撤销成功。撤销失败或无法确认已消费输入的归属时，宿主强制结束所属进程并保留状态不明。已运行回合的中断拒绝或终态等待到期同样强退并保留状态不明；重复停止共用同一操作和期限，真实终态取消本轮计时器。用户提示说明后台子代理会随进程停止，独立异步任务仍可能执行；用户核对副作用后才能重试。任务结果仍用原生工具输出，不伪装成用户输入；包内队列不接受工具输出。`turn/start.toolOutput` 与普通直接输入一样会被活跃回合吸收，仅凭返回的原生回合 id 无法证明新建。任务结果接续的交付取决于独立回合准入，不得把后台汇报绑定成接续回合，也不得给汇报绑定新运行授权。

桥接调用绑定可信用户、会话、进程代次、原生线程、回合、调用、工具和参数摘要。重放按原生调用身份去重，HTTP 请求序号不决定身份。参数规范化复用任务结果已有的 JSON 排序机制，公共定义放入 shared，路由只解析输入和调用服务。

验证从驻留管理模块、`codexRuntime.run`、任务桥接 HTTP 接口进入。每个逻辑修复先复现失败，再运行对应测试；最终运行全量后端与前端测试、类型检查、lint、构建、相关产品代码覆盖率，以及本地假模型上游配合真实 app-server 的探针。真实账号后台子代理与辅助标题线程验收单独报告，不以模拟通过代替。交付前执行独立代码审查和独立产品评审。


## 任务结果接续的进程策略

普通聊天跨轮驻留，任务接续则在管理模块确认会话没有活动后释放闲置进程，再用同一模块创建一次性进程恢复原生线程并提交工具结果。活动包括初始化、回合、队列判定、后台代理、汇报和审批。活动会话返回忙，持久投递队列稍后再试。网关先检查完整活动状态，管理模块在独占借用处同步复查；忙状态在尚未提交时向派发器透传，不能变成人工核对。一次性进程在借用和提交的间隙同样占用会话，其他借用和回收不能复用或终止它。结束和失败按进程代次清理。代价是每次任务接续增加进程启动与线程恢复；它不是同进程任务接续的验收结果。

`rootTurnId` 不承担请求随机标记：包内引擎虽然只在新建回合采用传入根 id，但字段表示真实因果链，随机 id 会引用不存在的回合；返回时识别出吸收也不能撤回已经送入的工具结果。
