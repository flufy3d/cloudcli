# 并行开发工作树

> 基准： 2.10.0 / 2026-10-19

`npm run worktree:*` 让多条改动线（多个终端、多个 AI 会话、子 Agent）同时在这个仓库里干活，互不踩脚。脚本调用
nexus-kit 的公共命令 `nexus-devflow worktree`，本仓不保留实现副本。本机通过 `~/.local/bin/nexus-devflow` 软链到
`~/workspaces/nexus-kit/packages/devflow/dist/cli.js`，PATH 上找不到这个命令时所有 `worktree:*` 脚本都会失败。
建、合、收的完整机制（只快进的理由、合入锁、回收判定）以 nexus-kit 的
`docs/架构算法/并行开发与发版.md` 为准，本篇只写 cloudcli 的接线和本仓差异。

三条不变量：合进 main 的每个提交都先在工作树里验证过；并行线各用各的目录和端口；回收不丢东西。

## 一条改动线的一生

拿 `feat/login` 从头走一遍：

1. 在主仓库执行 `npm run worktree:new feat/login`。命令在 `.worktrees/login` 建出工作树，从 main 新建分支，在
   新树里跑 `npm ci --include=dev` 装依赖（需要几分钟），并登记开发端口。第一棵树分到 3011，第二棵 3021，依此加 10；分配时
   避开所有已登记的和正在监听的端口。端口写在这棵树自己的 git 目录（`.git/worktrees/login/nexus-port`），随树
   一起消失。
2. 命令结尾打印的 `--port P --strictPort` 是 nexus-kit 面向 vite 预览的通用提示，对本仓不适用。本仓用
   `SERVER_PORT=3011 VITE_PORT=3012 npm run dev` 启动；服务端和 vite 本来就认这两个环境变量。
3. 在工作树里开发、提交、验证，浏览器开 `http://localhost:3011`。
4. 做完后在工作树执行 `git rebase main`，在变基后的代码上重新验证。
5. `cd` 回主仓库，单独执行 `npm run worktree:merge feat/login`。如果主仓库没检出 main 或者不干净，命令拒绝；
   如果 main 和分支分叉，命令拒绝并提示回工作树变基；否则只做快进。合入后在主仓库跑 `npm ci --include=dev && npm run build`，
   失败时非零退出，意思是已合入但没通过验证，必须继续修。
6. 在主仓库执行 `npm run worktree:rm login` 回收。如果当前 shell 还站在 `.worktrees/login` 里，命令拒绝，因为
   删掉目录会让这个 shell 失效。回收时先删工作目录在树内的 pm2 应用，再停树里起的服务；有未提交改动或
   `temp/` 里的手写脚本这类删了就找不回的文件时拒绝执行，确认都不要了加 `-- --force`。分支保留。

## 本仓配置

配置写在仓库根的 `nexus.config.json` 的 `worktree` 段，字段含义以 nexus-kit `packages/devflow/src/config.ts` 的
注释为准。和 nexus-kit 默认值不同的地方：

- 工作树放仓内 `.worktrees/`（已 gitignore），不放仓库同级目录。
- 端口从 3001 起：主仓库开发服务端是 3001，工作树从 3011 开始。
- 共享项（share）为空。开发数据库不共享，并行分支各自迁移表结构，共享会互相打架。
- 回收白名单补了 `dist-server`、`dist-server.next`、`dist-server.old`、`release`、`.desktop-build` 这些本仓构建
  产物，以及 `.husky/_`（`npm ci` 触发 `prepare: husky` 时在树里生成，不补的话每次回收都被它拦下）。`temp/`、`tmp/` 刻意不加：本仓习惯在里面放手写脚本，回收时必须拦下确认。
- 建树和合入后用 `npm ci --include=dev`。package.json 与 package-lock.json 不同步时 `npm ci` 直接报错；代价是
  每次建树、合入都要全量装一遍依赖。`--include=dev` 不能省：从 cloudcli 生产实例里开的 Claude 会话会继承 PM2 的
  `NODE_ENV=production`，npm 因此默认跳过 devDependencies。工作树里的缺失还会被掩盖：`npm run` 会把上级目录的
  `node_modules/.bin` 加进 PATH，`prepare` 里的 husky 借用主仓库那份照常跑通。到主仓库合入时 `npm ci` 先清空
  node_modules，`husky: command not found`，合入后验证失败。
- 不用发版锁。本仓发版走 AGENTS.md 里的发版流水线，不经 `nexus-devflow release`。

## Claude Code 钩子

`.claude/settings.json` 把 WorktreeCreate、WorktreeRemove 钩子接到 `nexus-devflow worktree hook-create` 和
`hook-remove`。`claude --worktree` 和子 Agent 的 `isolation: "worktree"` 因此走同一套建树逻辑：分支名
`worktree-<名>`，起点取发起会话当前的 HEAD，同名再开时复用既有工作树，同样跑 `npm ci --include=dev` 并登记端口。回收钩子
额外删除已经全部合入 main 的 `worktree-*` 分支。`.gitignore` 只放行 `.claude/settings.json`，`.claude/` 下的
其余本地文件仍不入库。
