# 跨路行身份（阶段 3）

> 状态：3a、3b 已实施（2026-09-18）；3c 待实施
> 目标：让实时与历史两路靠**身份**对账，而不是靠时钟和文本相似度猜

## 现状勘察：标准在，但只有一家喂它

`NormalizedMessage.providerRowKey` 是协议为"同一行在两路上的身份"设计的字段，
文档写得很清楚：它是唯一不依赖时钟、也不依赖推断回合位置的跨路身份。

**全仓只有 antigravity 设置它。**

```
server/modules/providers/list/antigravity/antigravity-sessions.provider.ts   2 处
（其余五家：0 处）
```

于是 claude / codex / cursor / opencode / zcode 的 assistant 文本对账，
**全部落到 `sessionMessageTurnDedupe.ts` 的启发式路径**，那里叠了两层猜：

1. **回合边界靠挂钟**——`allChronological = [...serverMessages, ...realtimeMessages].sort(compareMessagesChronologically)`，
   把两台机器的时间戳混排后找"前一条用户消息"。这正是阶段 0 从显示合并里拿掉的那件事，
   去重路径还留着。该文件的注释自己承认：clock skew 会把一条较旧的实时行挂到较新的持久化回合上。
2. **回合归属靠用户消息文本相等**——从后往前找 `content` 相同的服务端用户行。
   重复提示词（"继续"、"好"、"go on"）会绑到错误的回合。

最后由 `isAssistantTextMatch` 用「去空白相等」或「前缀且 `minLen >= 20` 且
（比例 ≥ 0.75 或 `minLen >= 100`）」判定是否同一行。

这就是"流式与非流式消息重复"反复出现的结构性原因：
**身份机制早就设计好了，但五家引擎没有实现，前端只能猜。**

## Codex 的身份是现成的

Codex 两路都有原生行 id，只是历史那路没把它带出来：

| 路径 | 位置 | 现状 |
| --- | --- | --- |
| 实时 | `normalizeMessage` 的 `case 'agent_message'` | 有 `itemId`（SDK `item.id`），已用作消息 id |
| 历史 | `getCodexSessionMessages` 的 `payload.type === 'message'` | `payload.id` **读到了但没带出来**，紧邻的计划卡分支正在用它 |

计划卡分支把 `payload.id`（历史）与 `itemId`（实时）当作同一身份使用，
这是两者同属一个 id 空间的直接证据。

Claude 情况不同：历史行有 `uuid`（已用作 `transcriptAnchorId`），
但实时 SDK 事件没有暴露同一个 id，**不能凭空造**——协议明确要求
"providers must omit it when no stable native identity is available"。

## 切片

### 3a Codex 行身份（本次提案）

1. 历史读取把 `payload.id` 带到紧凑条目上。
2. `normalizeHistoryEntry` 的 assistant 分支据此设置 `providerRowKey`。
3. 实时 `agent_message` 分支设置 `providerRowKey: itemId`。
4. 适配器层测试钉住：同一条 Codex 回复，两路归一化出**相同的 `providerRowKey`**。

做完之后 Codex 的 assistant 文本走 `reconcileProviderRowText` 的身份路径，
不再进文本相似度分支——而 Codex 正是本轮最初报障的引擎。

### 3b 去重路径改用因果锚点

把 `isAssistantTextEchoedInSameTurnOnServer` 里的挂钟混排换成阶段 0 已经建立的因果锚点，
与显示合并保持同一套口径。无身份可用的引擎仍需要它，但不该再由时钟裁决回合。

**依赖 3a 先落地**：先把有身份的引擎摘出去，剩下的失败面才小到可以安全改动。

### 3c 其余引擎的身份盘点

逐个核对 cursor / opencode / zcode 的两路是否存在可复现的原生行身份。
有就接上，没有就**明确记录为没有**，而不是留着让人以为总有一天会自动变好。

## 3a 的验收

- 同一条 Codex 回复，实时与历史归一化产出相同且非空的 `providerRowKey`（测试钉住）
- 该 key 在两路都能复建，不来自任何本端生成的值
- 既有 codex 测试、前后端 typecheck、全量测试、构建通过；lint 零新增告警
