# Codex 会话标题验收

> 冻结快照：2026-10-21；版本 2.10.0；工作树 `codex-title-slice1`

## 实现与同机制修复

成功的正常 Codex 用户回合异步提交标题任务。常驻、关闭驻留和容量回退均可提交；任务服务串行去重、检查资格、生成独立临时标题、先保存原生名称再条件更新本地名称，并发送仅元数据广播。开关默认开启，可以通过 providers 设置接口关闭并持久保存。失败、停止及工具结果接续不提交。

独立审查发现容量回退时仍误走驻留提交和清理判断。失败测试复现后，提交、停止、代理结算与连接释放均改为检查实际进程所有权。认证目录问题同时排查模型、MCP、技能、历史与监听路径；用户级读取统一使用引擎的 CODEX_HOME，工作区目录和独立的 ~/.agents 目录保留原有规则。

真实引擎拒绝只有 enabled=false、没有传输配置的不存在 MCP 项。隔离配置只禁用实际配置的服务器，宿主桥接存在时也禁用；可控模型检查工具列表为空。标题启动晚于截止、且尚未收到回合公告时，管理模块保留晚到应答的清理责任，只中断标题回合。

浏览器搜索场景发现标题副作用放在条件挂载的 Projects 列表，导致顶部名更新而浏览器标题不变。标题副作用移到常驻工作区状态层。五引擎回归覆盖 Codex、OpenCode、Claude、ZCode、Antigravity。独立产品评审又复现自动改名擦掉后台 [Done] 提醒；共享标题入口保留同会话标记，用户返回两秒后移除，切换会话清理旧通知。

## 限制

总截止时间从入队起计算三十秒，后排任务可能尚未开始就过期；下次正常聊天成功后再尝试，没有定时补偿。模型请求会消耗账号额度；配额快照只观察接口返回，期间存在其他请求，不能证明独立保留桶或免费。原生接口不支持条件写入，另一客户端在最后一次读取与保存之间改名仍有竞争窗口。

本轮没有运行部署命令，没有重启 PM2，没有修改生产会话或生产认证。
