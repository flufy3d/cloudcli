这是仓库修复的验收快照。生产服务没有部署或重启。

## 原因与范围

PM2 记录显示，2026-10-18 08:50:37–39，CloudCLI 的 RSS 达到 1,295,548,416 字节，超过 1 GiB 配置门槛，触发自动重启。08:54 是用户估计的时间。

原 OpenCode 展示链路将工具结果中的内嵌图片序列化进消息，同时被重连缓存和历史读取保留。早期真实会话取样包含 51 份图片，编码正文约 90 MiB。该会话后来已无法从真实数据库读取，最终对照使用模拟数据，不能视为原现场复现。

Claude、Codex、OpenCode、ZCode 的真实归一化入口测试确认了内嵌图片保留风险。Cursor 的批量二进制读取及 Antigravity 的整文件读取也有峰值放大风险。六个 provider 均纳入共用展示压缩边界和逐条、逐行历史读取。

图片正文写入鉴权资源文件，大工具文本保留预览及全文下载，用户输入保留完整原文。回放缓存按单条、单运行及进程总字节预算淘汰，并报告重放缺口。历史缓存按展示数据计费。HTML、PDF、JSON 导出内嵌资源，离线附件无需 React 事件。

## 内存对照

构建仓库后运行：

```sh
node scripts/probe/provider-result-memory.mjs --baseline /Users/azrael/.cloudcli/runtime/node_modules/cloudcli
```

探针生成 51 张不同的模拟图片，编码正文合计 94,656,000 字节，调用真实 OpenCode translator、回放 registry 与历史读取器。重放后连续读取四次历史；每次断言总数 51、返回 20 条。探针逐条统计回放序列化体积，避免一次序列化全部缓存额外制造峰值。

| 指标 | 旧运行目录构建 | 仓库修复构建 |
| --- | --- | --- |
| 最后一次峰值 RSS | 606 MiB | 328 MiB |
| 相邻一次峰值 RSS | 590 MiB | 345 MiB |
| 最后一次耗时 | 1,728 ms | 3,094 ms |
| 回放事件序列化体积 | 189,329,056 字节 | 24,400 字节 |

图片落盘增加处理时间。内存结果来自同规模隔离进程，受 GC、文件缓存和运行环境影响。探针没有模拟生产的全部并发、会话和连接，不能据此承诺线上总 RSS 或永不触发 PM2 门槛。当前构建通过探针设定的 512 MiB 隔离进程上限。

早先报告的 1,406 MiB 含探针一次性序列化全缓存的额外开销，不作为收益依据。
